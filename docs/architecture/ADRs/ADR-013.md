## Contexto

A EOAP requires standardized logging for debugging, monitoring and audit.

## Decisão

Logging pattern: `[EOAP][Module][Entity][Correlation_ID][Outcome]`

## Rationale

- Consistência de logging
- Facilita debugging
- Correlation ID tracking
- Facilita monitoring
- Alinhado com best practices

## Alternativas Consideradas

### Alternativa 1: Logging ad-hoc
**Rejeitado**: Inconsistente, difícil de debug

### Alternativa 2: Logging sem correlation ID
**Rejeitado**: Impossível trace end-to-end

## Consequências

### Positivas
- Consistência
- Debugging facilitado
- Trace end-to-end

### Negativas
- Overhead de implementação
- Requer disciplina

## Implementation

- Pattern: `[EOAP][Module][Entity][Correlation_ID][Outcome]`
- Examples:
  - `[EOAP][Offboarding][user_123][corr_456][SUCCESS]`
  - `[EOAP][RiskEngine][change_789][corr_456][FAILED]`
- Log levels: ERROR, WARN, INFO, DEBUG
- Correlation ID propagation em todos os flows
