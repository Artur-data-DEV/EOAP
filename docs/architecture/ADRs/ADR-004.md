## Contexto

A EOAP requer orquestração de processos complexos (onboarding, offboarding, risk assessment) com integrações e validações.

## Decisão

Flow Designer como orquestração primária; subflows de propósito único; lógica complexa em Script Includes.

## Rationale

- Flow Designer é visual e fácil de manter
- Subflows reutilizáveis
- ATF testing nativo
- Error handling nativo
- Alinhado com best practices ServiceNow

## Alternativas Consideradas

### Alternativa 1: Script Includes para toda orquestração
**Rejeitado**: Menos visível, harder to maintain, no ATF nativo

### Alternativa 2: Business Rules para orquestração
**Rejeitado**: Menos expressivo para processos complexos

## Consequências

### Positivas
- Visibilidade e manutenção facilitada
- Subflows reutilizáveis
- ATF testing nativo

### Negativas
- Limitações em lógica muito complexa
- Requer Script Includes para edge cases
