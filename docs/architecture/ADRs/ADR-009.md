## Contexto

A EOAP requires clear ownership for access governance and approval routing.

## Decisão

`x_eoap_access_owner` como referência de governança de acesso — distinto de owned_by OOB.

## Rationale

- Governança de acesso específica EOAP
- Approval routing baseado em access owner
- Distinção de owned_by (technical)
- Alinhado com SoD

## Alternativas Consideradas

### Alternativa 1: owned_by OOB apenas
**Rejeitado**: owned_by é technical, não governance

### Alternativa 2: Access owner em tabela separada
**Rejeitado**: Duplicação, overhead de manutenção

## Consequências

### Positivas
- Governança clara
- Approval routing facilitado
- Distinção de technical vs governance

### Negativas
- Requer preenchimento manual inicial
- Overhead de manutenção

## Implementation

- Campo x_eoap_access_owner em cmdb_ci_business_app
- Campo x_eoap_access_owner em cmdb_ci_service_discovered
- Reference: sys_user (role x_eoap_access_owner)
