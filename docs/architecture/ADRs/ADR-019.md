# ADR-019 — Avaliação OOB antes de customização

## Contexto

A EOAP requires evaluation of OOB products before custom development.

## Decisão

Produtos avaliados: HRSD, IGA, GRC, Compliance Audit, IntegrationHub; cinco tabelas custom aprovadas por gap semântico.

## Rationale

- OOB First principle
- Avaliação de gap semântico
- Reduz custom code
- Alinhado com best practices

## Alternativas Consideradas

### Alternativa 1: Custom development sem avaliação OOB
**Rejeitado**: Viola OOB First, overhead de manutenção

### Alternativa 2: IGA OOB para tudo
**Rejeitado**: IGA OOB insuficiente para entitlement lifecycle governado

## Consequências

### Positivas
- OOB First
- Reduz custom code
- Avaliação estruturada

### Negativas
- Overhead de avaliação
- Gap semântico requer custom

## Implementation

- HRSD: Avaliado, gap semântico para governança específica
- IGA: Avaliado, insuficiente para entitlement lifecycle governado
- GRC: Avaliado, gap semântico para risk calculation específico
- Compliance Audit: Avaliado, gap semântico para audit trail específico
- IntegrationHub: Avaliado, adotado para integrações
- Cinco tabelas custom aprovadas
