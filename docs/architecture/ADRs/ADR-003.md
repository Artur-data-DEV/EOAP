## Contexto

A EOAP requer isolamento de código, dados e configuração para evitar conflitos com outras aplicações e facilitar upgrades.

## Decisão

Implementar EOAP como scoped application `x_eoap` com cross-scope rules explícitas (ADR-017).

## Rationale

- Isolamento de código e dados
- Facilita upgrades de plataforma
- Evita conflitos com outras aplicações
- Governança clara de escopo
- Alinhado com best practices ServiceNow

## Alternativas Consideradas

### Alternativa 1: Global scope
**Rejeitado**: Risco de conflitos, difícil de governar, não alinhado best practices

### Alternativa 2: Múltiplas scoped apps
**Rejeitado**: Overhead de manutenção, complexidade desnecessária

## Consequências

### Positivas
- Isolamento claro
- Facilita upgrades
- Governança simplificada

### Negativas
- Requer cross-scope rules para CMDB
- Overhead de configuração inicial

## Implementation

- Scoped application `x_eoap`
- Prefix `eoap`
- Cross-scope ACLs (ADR-017)
- Cross-scope Business Rules
