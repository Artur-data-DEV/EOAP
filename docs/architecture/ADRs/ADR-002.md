## Contexto

A EOAP requer lógica de decisão complexa para roteamento de aprovação, cálculo de risco e ações de lifecycle.

## Decisão

Política declarativa em Decision Tables; Script Includes para agregação e operações não expressáveis declarativamente.

## Rationale

- Decision Tables são visuais e fáceis de manter
- Business users podem modificar sem código
- Versionamento nativo
- ATF testing nativo
- Reduz dependência de desenvolvedores

## Alternativas Consideradas

### Alternativa 1: Script Includes para toda lógica
**Rejeitado**: Menos visível, harder to maintain, requires developers

### Alternativa 2: Business Rules
**Rejeitado**: Menos expressivo para lógica complexa

## Consequências

### Positivas
- Visibilidade e manutenção facilitada
- Business users podem modificar
- Versionamento e testing nativos

### Negativas
- Limitações em lógica muito complexa
- Requer Script Includes para edge cases

## Implementação

- DT_Access_Approval_Routing
- DT_Risk_Weights
- DT_Risk_Banding
- DT_Lifecycle_Actions
- Script Includes para agregação e operações complexas
