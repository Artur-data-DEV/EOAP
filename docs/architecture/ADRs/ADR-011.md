## Contexto

A EOAP requires a first-class registry for user access entitlements with lifecycle management.

## Decisão

`x_eoap_user_access` como entitlement de primeira classe.

## Rationale

- Entitlement lifecycle governado
- Audit trail completo
- Recertification facilitada
- Reconciliation com IAM
- Alinhado com best practices

## Alternativas Consideradas

### Alternativa 1: sys_user_has_role
**Rejeitado**: Insuficiente para governança granular, sem lifecycle

### Alternativa 2: RITM permanente
**Rejeitado**: RITM é request, não entitlement, overhead de manutenção

## Consequências

### Positivas
- Entitlement lifecycle governado
- Audit trail completo
- Recertification facilitada

### Negativas
- Overhead de tabela customizada
- Requer reconciliação com IAM

## Implementation

- Tabela x_eoap_user_access
- Campos: user, application, status, valid_from, valid_to, etc.
- Lifecycle: requested → pending_approval → approved → active → expired/revoked
- Reconciliation job diário
