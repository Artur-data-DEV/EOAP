## Contexto

A EOAP requires efficient queries for performance and scalability.

## Decisão

Índices definidos Sprint 0 por padrão de consulta (documentados no SDD por tabela).

## Rationale

- Performance otimizada
- Escalabilidade
- Padrão de consulta documentado
- Alinhado com best practices

## Alternativas Consideradas

### Alternativa 1: Índices ad-hoc
**Rejeitado**: Performance degradation, não escalável

### Alternativa 2: Sem índices
**Rejeitado**: Performance inaceitável

## Consequências

### Positivas
- Performance otimizada
- Escalabilidade
- Padrão documentado

### Negativas
- Overhead de índices
- Storage overhead

## Implementation

- Índices por tabela (documentados no SDD)
- x_eoap_user_access: user, application, status, valid_to, correlation_id
- x_eoap_audit_trail: entity_type, entity_sys_id, event_type, actor, correlation_id, timestamp
- x_eoap_event_processing: idempotency_key (unique), status, event_type, correlation_id
- x_eoap_risk_evidence: change_request, risk_factor, band, calculated_on
- Review trimestral de performance
