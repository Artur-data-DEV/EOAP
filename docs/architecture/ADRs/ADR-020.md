# ADR-020 — Staging tables para integração

## Contexto

A EOAP requires integration with external systems (HRIS, IAM) for employee lifecycle and access reconciliation.

## Decisão

`x_eoap_staging_employee`, `x_eoap_staging_access_recon` — loose coupling; coalesce keys; erro por linha.

## Rationale

- Loose coupling com sistemas externos
- Coalesce keys para idempotência
- Erro por linha (fail-safe)
- Facilita debugging
- Alinhado com best practices

## Alternativas Consideradas

### Alternativa 1: Integração direta sem staging
**Rejeitado**: Tight coupling, difícil debugging, não fail-safe

### Alternativa 2: Staging sem coalesce keys
**Rejeitado**: Sem idempotência, risco de duplicação

## Consequências

### Positivas
- Loose coupling
- Idempotência
- Fail-safe
- Debugging facilitado

### Negativas
- Overhead de tabelas staging
- Complexidade de implementação

## Implementation

- x_eoap_staging_employee: employee_sys_id, event_type, event_data, processed, error_message
- x_eoap_staging_access_reconciliation: user_sys_id, application_sys_id, technical_access, governed_access, drift_type
- Coalesce keys: employee_sys_id, user_sys_id + application_sys_id
- Erro por linha: não falha batch inteiro
- Processamento assíncrono
